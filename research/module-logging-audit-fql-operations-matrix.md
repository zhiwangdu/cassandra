# Module: Logging, Audit Log, And Full Query Log Operations Matrix

## 范围

本矩阵补充 `module-operations-observability.md` 与 `module-observability-internals.md` 中的 logging 深水区，聚焦普通 logback 日志、运行时 logger 调级、`system_views.system_logs`、audit log、full query log、共享 `BinLog` 队列/归档机制和 nodetool/JMX 操作边界。不重复展开 tracing、diagnostic events 或完整 JMX auth。

## 运维判读

- 普通 daemon 日志、audit log、FQL 是三条不同路径：logback files 面向进程诊断，audit log 面向用户行为审计，FQL 面向 query replay/分析。不要用 `system_views.system_logs` 代替 audit/FQL。
- 动态 log level 适合临时排障；排障结束后应清理或 reload 配置，避免 DEBUG 长期保留在 runtime。
- audit/FQL 的 `block=true` 保证少丢日志但可能阻塞请求；`block=false` 保证请求路径更轻但会丢记录。这个取舍必须和合规要求一起评估。
- archive command 是本地命令执行能力，默认由 YAML gate 关闭；打开前要确认 JMX 权限边界和脚本安全。
- audit/FQL 目录不能共用；`BinLog.currentPaths` 会拒绝同路径，但部署时仍应分开规划磁盘配额和归档。
- FQL 记录完整 query/batch payload 和 query options；它可能包含敏感业务数据，不应只按普通 debug log 处理。
