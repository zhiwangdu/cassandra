## 范围

本矩阵补充 `module-bloom-filter-index-summary.md` 与 `module-bloom-sstable-index-deep-dive.md`：聚焦 Bloom filter、`Filter.db`、BigTable `Summary.db`、BTI `Partitions.db` preload、metrics/JMX/nodetool 可见性和现有测试缺口。不重复展开完整 SSTable reader/writer 格式。

## 运维判读

- `Filter.db` 缺失或损坏时先区分 SSTable format 与 open mode：Big online open 可 rebuild filter/summary，BTI online open 只能 rebuild filter，offline/no-validation 更可能退化到 `AlwaysPresent`。
- `bloom_filter_fp_chance = 1.0` 是明确关闭 informative Bloom 的表级选择；这会降低 Bloom off-heap/disk 占用，但 miss-heavy point read 会转移到 index lookup。
- Big 的 `IndexSummaryOffHeapMemoryUsed` 与 Bloom off-heap 是两类成本；BTI 没有 `IndexSummaryOffHeapMemoryUsed`，应关注 Bloom + partition trie open/preload 成本。
- Bloom false positive ratio 升高通常说明 miss-heavy workload、过宽松 FP chance、旧 SSTable 未 rewrite 或 SSTable 数量过多；它影响 IO/latency，不影响读正确性。
- 修改 `min_index_interval`/`max_index_interval` 只影响新 summary 或 resize/rebuild 后的 summary；不能把 schema 已改当作所有旧 SSTable 已完成重采样。

## 当前缺口

- `bloom_ops_legacy_mixed_version_gap` 仍缺真正 distributed/upgrade 场景：old Bloom filter fixture、Big/BTI selected format 切换、`storage_compatibility_mode`、automatic SSTable upgrade、streaming/loader fallback 和 rollback 组合验证。
- 现有 checker `research/tools/check-bloom-index-summary-operations-drift.py` 只证明源码/测试/doc baseline 未漂移；它不会替代上述分布式兼容测试。
